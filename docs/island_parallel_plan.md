## 为什么可行：岛之间真的不相交

顺序冲量求解器（Gauss-Seidel）的结果依赖**接触的处理顺序**，所以「按刚体对重排接触」
这类优化会改变物理结果，不能随便做。但 island 并行不违反这一点：

* 把刚体按「接触 + 关节」的连通性切成若干连通分量（island）；
* **岛与岛之间没有任何接触/关节共享刚体**，因此岛 A 的求解不会读也不会写岛 B 的状态；
* 在一个岛内部**完全保持现有的接触顺序**（全局顺序在岛内的子序列），
  所以每个岛的求解结果与串行时逐位相同；
* 于是：并行 ≠ 改变结果。`golden_digest_is_stable` 与 60 步参考都应当**不变**。

反过来：只有「岛内顺序」和「浮点运算顺序」都不动，才能保住这个结论。

## 数据结构（全部跨步复用，稳态零分配）

```
union-find: Vec<u32>          // 按刚体下标，路径压缩（迭代写法，禁止递归爆栈）
island_of:  Vec<u32>          // 刚体 → 岛编号（-1/哨兵表示「不属于任何岛」）
island_bodies: Vec<u32>       // 展平的岛 → 刚体下标（CSR）
island_ranges: Vec<(u32,u32)> // 岛 → island_bodies 的区间
island_contacts: Vec<u32>     // 展平的岛 → 接触下标（CSR）
island_contact_ranges: Vec<(u32,u32)>
island_joints: Vec<u32>       // 关节同理
```

**只有「清醒的动态体」参与划分**：静态体（`inv_mass == 0`）和睡着的体不写状态，
它们可以同时出现在多个岛的接触里（只被读，不被写），因此不参与连通性合并——
这也正是「接触另一端是地板」时不会把全世界并成一个岛的原因。

## 约束如何归组（第二步的第一件事）

`Islands` 目前只存「岛 → 刚体」。并行求解还需要「岛 → 约束」，做法：
把 `union_pair(a, b)` 换成 `union_constraint(index, a, b)`，在合并的同时把约束下标
记进一条复用的 `Vec`（每步清空），`finish()` 里再对它做一次 CSR（按岛分组，
**组内保持全局顺序**——这是「结果不变」的前提）。
接触与关节各一条 CSR，因为它们的求解函数不同、迭代顺序也不同（每个迭代里
先接触后关节）。

## 求解流程（native 多线程路径）

1. `prepare` 之后，用当步的接触表 + 关节表建并查集（顺序遍历 → 结果确定）；
2. 按岛归组接触与关节（CSR）；
3. 若 `islands >= 2 && 刚体数 >= 阈值 && !cfg(target_arch = "wasm32")`：
   * 为每个岛**收集一份本地 `BodyView`**：岛内清醒动态体 + 这些接触/关节涉及到的冻结体
     （冻结体被复制进多个岛没关系——它们永远不会被写）；
   * 把接触/关节的 `a/b` 下标重映射到本地数组（本地映射表用 `Vec<u32>` + 哨兵表示「不在本地」）；
   * `std::thread::scope` 按岛分片，每个线程跑**同一个** `solve_velocity` / `solve_position`
     实现（抽成接受「接触下标切片 + 本地视图」的函数；接触顺序仍是岛内子序列顺序）；
   * 线程数取 `min(可用并行度, 岛数)`，且要有上限（避免 2000 个单体贴开 2000 个线程）；
4. 合并：只把每个岛的**清醒动态体**速度写回全局 `views`（岛间不相交 → 无竞争）；
5. 其余阶段（积分、写回刚体、宽相、窄相、准备）保持单线程——它们的占比小，
   而且并行化收益/复杂度比不划算。

## 休眠：整岛计时

现在每个刚体各自计时入睡，堆叠场景里会出现「一半睡着、一半还在抖」的状态。
改为：**整个岛都低于阈值才让整岛入睡**；岛内任一刚体被唤醒（新接触、外力、关节驱动）
则整岛一起醒来。这比逐体计时更正确（不会留下半个睡眠的堆叠），实际也更省时间
（岛内不再有「睡着的体被清醒的邻居反复唤醒」）。

注意：这条**会改变模拟结果**（睡眠时机变了），所以它必须和并行分开做，
并且要按两层的锁定流程重新标定：重跑 60 步参考表、更新黄金摘要、复核
「长跑物理不变量」与 CLI 的睡眠计数测试。并行那一步则应当摘要不变。
