## Problem and acceptance scope

Round217 established that a later equal-half pair visit can recompress an earlier separated pair in free space. The registered three-particle operator failed after both ABC/CBA fixtures completed; the separate 125-particle sealed target also remains unmet. See [chain evidence](particle_chain_recompression.md) and [sealed target](sealed_particle_separation.md). Neither fact proves that this proposed solver will converge, fit the budget, or satisfy the full-step target.

The proposed experiment solves one frozen, coupled inequality system for one position correction. It does not repeat the existing separation operator, increase the four PBF density iterations, add substeps, or change the existing 1/60 timestep, initial state, container, or geometric tolerance. The initial implementation, if authorized, is a cfg(test) experimental helper and test wrapper, not a production feature or supported user option. A later production mode requires separate approval.

Supported boundary domain is empty boundaries or static, non-sensor, single-part Box/Plane bodies with unit scale and valid finite geometry/transforms. No dynamic/kinematic body, compound, mesh, other shape, or nonunit scale is silently ignored: an unsupported participating boundary makes the whole attempt Uncertified. Sensors are excluded from collision boundaries under existing semantics. Box extraction must use its actual geometry, not an AABB substitute for another shape. Plane normals must be finite, nonzero and normalized consistently. No general mesh, arbitrary concavity, moving-boundary or full pressure support is promised.

## Frozen problem and units

For N particles, freeze the actual stored f32 coordinates at the helper entry, widen them to f64 before subtraction, and freeze finite positive particle masses m_i. Let x_i be these frozen positions, delta_i the unknown displacement and D the stored-radius diameter 2*f64::from(radius). Minimize one half sum_i m_i*||delta_i||² subject to the following fixed rows.

For every unordered pair i<j, use n_ij=(x_i-x_j)/||x_i-x_j|| and the inequality n_ij dot (delta_i-delta_j) >= D - n_ij dot (x_i-x_j). Include all pairs, including initially separated pairs; do not use the prediction neighbor list as the mathematical graph and do not remove a row because it starts slack. For exactly coincident positions use deterministic +X with the same i<j convention; this direction choice does not guarantee joint feasibility. Reject nonfinite inputs rather than treating them as absent constraints.

For every particle and every supported boundary body, extract a frozen world surface point S and outward unit normal N_b from the existing closest_surface API/transform semantics. Define signed=(x_i-S) dot N_b, and impose N_b dot delta_i >= radius-signed. This freezes a supporting half-space, not a moving nearest-feature query during the solve. A Box's exterior nearest-point normal supports the convex body; interior points use the API's outward normal, not normalize(x-S), which would point inward. At the sealed fixture all six boxes select the six cavity-facing faces, so these six constraints reproduce the radius-shrunken cavity. Away from that fixture the selected branch is conservative and may exclude otherwise legal routes around a box; failure is allowed and must be reported, never hidden by changing the branch to obtain acceptance. Exact-surface feature ties use a documented deterministic axis/feature order matching the geometry extraction. The API returns f32 surface/normal values; widen their stored components and normalize the world normal in f64 for the new experiment. Pair differences and direction normalization are instead computed entirely in f64 after widening both input coordinates. This deliberate new-mode arithmetic does not alter either old mode.

Use y_i=sqrt(m_i)*delta_i. Each pair row has six nonzero scalar coefficients: +n_ij/sqrt(m_i), -n_ij/sqrt(m_j); each wall row has three coefficients N_b/sqrt(m_i). The right-hand side b remains in physical metres. The scaled coefficient-vector squared norm aa must be finite and strictly positive. Do not substitute equal masses in independent algebra tests: the unequal-mass case must verify the transform and inverse transform.

Row order is stable: all pair rows in lexicographic i<j order, followed by boundary rows in particle-index, body-index, then deterministic feature order. The graph, coefficients, normals and right-hand sides remain fixed throughout all sweeps. Setup records the actual ordering for trace comparison.

## Fixed Hildreth dual update and bounds

Initialize all dual multipliers lambda=0 and all y=0. Perform exactly 128 complete sweeps over the same full stable row list. For a row a dot y >= b:

```text
lambda_new = max(0, lambda_old + (b - a dot y) / aa)
y += (lambda_new - lambda_old) * a
lambda = lambda_new
```

For a coordinate change t, the dual objective change is phi(lambda+t)-phi(lambda)=t*(b-a dot y)-0.5*t²*aa, constrained by t>=-lambda_old. Maximizing this concave scalar quadratic gives exactly the update above. This establishes the coordinate step, not fixed-budget global convergence.

Maintain one multiplier per row throughout the entire solve. A negative multiplier change must undo the row's earlier correction; do not reset lambda between sweeps or clamp the displacement update to positive increments. This is global dual coordinate optimization with shared particle variables, distinct from repeatedly applying independent equal-half pushes. No QR, trust box, extra convergence loop, adaptive sweep count, or hidden original-operator postpass is part of this registration.

Predeclare a hard cap of **32768 total rows, including every pair and every wall row**. After validating/counting eligible supported boundaries, compute N*(N-1)/2 + N*wall_count with checked arithmetic before traversing any particle pairs or allocating rows. Handle N<2 explicitly and return Uncertified on overflow. A 4000-particle request must be rejected from these counts, without first constructing/traversing its roughly eight million pairs. If the complete graph would exceed the cap, return Uncertified with the original entire predicted array unchanged. Never truncate rows, replace missing all-pair constraints by neighbors, or silently route selected N to a different success path. For the six-wall 125-particle fixture there are 7750 pair plus 750 wall rows, 8500 total. The cap intentionally does not support a 4000-particle complete graph. Setup remains O(N²), solver work O(128 E) with at most six row components, and storage O(E+N); these are bounds, not a measured performance guarantee. Overflow/nonfinite arithmetic during setup or iteration also returns Uncertified.

## Atomic result and certificates

The helper works in scratch storage. Its only successful outcome is Certified. Unsupported geometry, capacity failure, invalid mass/input, nonfinite arithmetic, unsatisfied rows or a failed geometric guard returns an explicit Uncertified reason and leaves the whole original predicted array intact. A preserved/fallback state is not a successful new solve. This helper contract does not authorize skipping a public physics step or silently advertising successful separation when a later production integration falls back; integration behavior needs its own reviewed API/status contract. If later approved, a minimal status field/getter on Fluid is preferable to silently extending FluidStats/scene reporting schemas. Its Certified meaning is limited to the end of this separation operator: later bubble/liquid coupling or other full-step position changes can invalidate it, so it cannot advertise an unverified final-world certificate. A future integration must define NotRun reset at every step (including empty/early-return paths), stale-state prevention and snapshot consistency. No status field, getter or public enum is authorized by this document.

After all 128 sweeps, require all of the following without changing the fixed budget:

1. Finite y, delta, multipliers and candidate coordinates; valid nonnegative multipliers and positive row denominators.
2. Every original linear constraint's violation at most **1e-7 m**, recomputed in physical form (n dot (delta_i-delta_j) or N_b dot delta_i), not by mistaking a mass-scaled variable or coefficient norm for a length tolerance. The product a dot y already has units of metres because a contains n/sqrt(m) and y contains sqrt(m)*delta; do not compare a normalized-by-aa residual against the length tolerance. This is a primal feasibility certificate; no unregistered KKT/objective-optimality tolerance is claimed. Independently reconstruct y_ref=A-transpose*lambda in fixed f64 row/component order; require max_i ||(y_i-y_ref_i)/sqrt(m_i)|| <=1e-7 m and use y_ref for the row certificate and proposed displacement. A mismatch rejects the attempt instead of concealing incremental accumulation drift.
3. Apply the candidate through the existing supported collision/sweep path as a safety guard, using frozen current boundary geometry and no replay of body motion. Materialize the actual returned f32 coordinates. If the guard changes any correction, recompute certificates on the guarded, stored result; a pre-guard feasible QP does not establish post-guard pair feasibility.
4. Independently widen these stored f32 positions to f64 and scan every unordered pair: distance >= D-1e-4 m. Check finite state/count/mass and every supported body's signed particle clearance >= -1e-4 m. This is not a solver-neighbor oracle. Preserve the exact six-inner-face oracle for the sealed cavity; for generic supported Box/Plane use independent analytic geometry, including box exterior Euclidean distance and interior sign, not the extraction helper itself as its only oracle.
5. All fixed linear rows also pass the 1e-7 m physical residual check after guard/f32 storage. F32 rounding can make this stricter certificate fail even if the 1e-4 m geometric target passes; the registered response is Uncertified, not tolerance adjustment or accepting only the pre-storage result.

The pair half-space inequality is sufficient for pair distance at least D in exact arithmetic, since a unit directional projection lower-bounds Euclidean norm. The selected convex-body support plane at offset radius is a sufficient safe side of that body; the union of all feasible safe branches is generally larger than the one chosen branch. These observations do not prove numerical feasibility, finite-budget convergence, or compatibility of all chosen branches. Fixed-direction coincident pairs and tightly packed configurations may yield an infeasible system. No claim of an infeasibility proof follows merely from reaching 128 sweeps: a failed certificate means Uncertified, with a budget/residual diagnostic.

## Independent algebra tests before physical candidate

Before evaluating a production candidate, use an independent small dense oracle, separate from sparse row extraction/update code. Cases and expected semantics are registered now:

- Two equal-mass free particles: dense analytic minimum-norm pair separation, unchanged position sum and no tangential drift; test a slack pair too.
- Unequal masses (for example 1 and 4): relative correction closes the deficit, mass-weighted displacement sum is zero, and endpoint movement ratio is inverse mass. Use analytic equations independently of y-coordinate implementation.
- A particle/wall row and a coupled two-particle/floor case: correct outward orientation, signed clearance and feasible solution, with independently known analytic active constraints. Include a permitted outward correction and a blocked inward request.
- Redundant/duplicate rows and an ordering control: the final certified physical constraints remain valid; do not assert unique dual multipliers for redundant constraints. Check that retained dual memory can decrease a prior multiplier rather than only adding pushes.
- Deliberately inconsistent half-spaces and a finite-budget nonconverged case: return Uncertified, preserve the complete original predicted array bitwise, and expose residual/cap/budget reasons without pretending the algorithm proved infeasibility.
- Unsupported shape/nonunit scale and complete-graph row-cap overflow: explicit Uncertified, no partial mutation, no dropped rows. Verify cap arithmetic includes wall rows.
- Guard/f32-storage damage: a passing pre-guard solve followed by a changed stored candidate must be rejected unless the full post-guard certificates independently pass.

Numerical comparisons in small analytic tests must state their units and use f64 controls. A dense reference with a different formulation, such as explicit enumeration of active subsets for these tiny systems, can independently check primal feasibility and the minimum-norm objective; do not duplicate Hildreth loops as the alleged independent reference. No numeric accuracy result exists yet.
